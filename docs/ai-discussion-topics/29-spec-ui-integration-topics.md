# AI Discussion Topics: Feature 29 — Spec UI Integration

Use these questions with an AI assistant to deepen your understanding of the patterns and decisions in this feature.

## On Lazy vs Eager Data Fetching

1. Feature 29 fetches the spec list only when the Specs tab is activated. What are the trade-offs between lazy (on-demand) and eager (on-mount) data fetching in sidebar components? When would you choose one over the other?

2. After a successful spec generation run, the list is refreshed by calling `fetchSpecs()` again. What are the alternatives to this "refetch on complete" pattern (e.g., optimistic updates, polling, WebSocket push)? Why is a simple refetch appropriate here?

## On Programmatic File Download

3. The download uses `URL.createObjectURL` + a hidden `<a>` click. Why doesn't just calling `fetch()` on a `Content-Disposition: attachment` endpoint trigger a browser download? What is the browser's actual behavior?

4. Why is it important to call `URL.revokeObjectURL` immediately after the `<a>` click rather than after a delay? What resource does the object URL hold?

## On Reusing Components

5. The same `RunTracker` component is used for both design runs and spec generation runs by rendering two instances with different props. What are the advantages of this design vs. creating a specialized `SpecRunTracker`? Are there any risks to rendering two instances that call `useRealtimeRun` simultaneously?

6. The `RunTracker` uses a `firedRef` to guard against double-firing. Why is this guard needed even though `useEffect` dependencies should prevent it from running twice?

## On Markdown Rendering

7. `react-markdown` is used with a custom component map instead of `@tailwindcss/typography` prose classes. What are the practical trade-offs between these two approaches for a dark-mode-only application with custom design tokens?

8. The `code` component checks for a `className` prop to distinguish inline code from code blocks. How does `react-markdown` pass this information, and why is this the standard detection pattern?

## On Security

9. The preview modal fetches spec content through the download API endpoint rather than reading the Vercel Blob URL directly. Beyond the credential exposure risk mentioned in the docs, what other security properties does the server-side fetch provide (e.g., access revocation, audit logging)?

10. The `previewContent` is rendered via `react-markdown` which outputs React elements, not `dangerouslySetInnerHTML`. Why does this matter from an XSS perspective, even though the content was generated by our own AI?

## On State Design

11. Preview content is reset to `null` each time a new spec is selected (before fetching). What bug would occur if this reset was omitted?

12. The `specCompletionHandledRef` mirrors the pattern of `completionHandledRef` in the design run flow. What concurrency scenario does this ref guard against in a React component?

## On Accessibility

13. Spec list items use `<div role="button" tabIndex={0}>` with `onKeyDown` instead of a native `<button>`. When is this pattern acceptable vs. when should you use a native `<button>` instead? What ARIA attributes might be missing?

14. The download button in each spec list item has `opacity-0 group-hover:opacity-100`. What accessibility problem does this create for keyboard-only users, and how does the `focus:opacity-100` class address it?
